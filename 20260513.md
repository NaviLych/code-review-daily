## 审查发现

### 🔴 Bug #1: Collections.synchronizedList() 虚假线程安全

**AI生成代码**：
```java
public class UserService {
    private List<User> activeUsers = Collections.synchronizedList(new ArrayList<>());
    
    public void processUsers() {
        for (User user : activeUsers) {
            if (user.isInactive()) {
                activeUsers.remove(user); // ConcurrentModificationException!
            }
        }
    }
}
```

**问题诊断**：
- **数据流**：输入List → 遍历+删除 → 输出修改后的List
- **边界条件**：多线程并发时，迭代过程中删除元素
- **根因**：synchronizedList只保证单个操作的原子性，不保证复合操作

**正确方案**：
```java
private ConcurrentLinkedQueue<User> activeUsers = new ConcurrentLinkedQueue<>();
public void processUsers() {
    activeUsers.removeIf(User::isInactive);
}
```

### 🔴 Bug #2: Virtual Thread + synchronized 性能杀手

**AI生成代码**：
```java
public class AccountService {
    public synchronized void transfer(Account from, Account to, BigDecimal amount) {
        from.withdraw(amount);
        to.deposit(amount);
        auditLog.record(...);
    }
}
```

**问题诊断**：
- **数据流**：账户转账 → 审计日志
- **边界条件**：高并发下synchronized阻塞Virtual Thread的carrier线程
- **性能影响**：实测50 req/s → 500 req/s（10倍差距）

**正确方案**：
```java
private final ReentrantLock transferLock = new ReentrantLock();

public void transfer(...) throws InterruptedException {
    if (transferLock.tryLock(5, TimeUnit.SECONDS)) {
        try {
            // 业务逻辑
        } finally {
            transferLock.unlock();
        }
    }
}
```

### 🟡 Bug #3: Double-Checked Locking 过度设计

**AI生成代码**：
```java
public class DatabaseConnection {
    private volatile Connection connection;
    
    public Connection getConnection() {
        if (connection == null) {
            synchronized (this) {
                if (connection == null) {
                    connection = createConnection();
                }
            }
        }
        return connection;
    }
}
```

**问题诊断**：
- 虽然volatile保证可见性，但代码过于复杂
- Java 22有更简洁的方案

**正确方案**：
```java
private static class ConnectionHolder {
    static final Connection INSTANCE = createConnection();
}
public Connection getConnection() {
    return ConnectionHolder.INSTANCE;
}
```

### 🟠 Bug #4: Structured Concurrency Scope泄漏

**AI生成代码**：
```java
public void processOrders(List<Order> orders) throws InterruptedException {
    try (var scope = new StructuredTaskScope.ShutdownOnFailure()) {
        for (Order order : orders) {
            scope.fork(() -> processOrder(order));
        }
        // 缺少 scope.join()！任务继续运行！
    }
}
```

**问题诊断**：
- fork后未join，Virtual Thread泄漏
- 严重时导致应用崩溃

**正确方案**：
```java
scope.join();
scope.throwIfFailed();
return tasks.stream().map(Subtask::get).toList();
```

### 🔴 Bug #5: CompletableFuture 异常吞没

**AI生成代码**：
```java
return CompletableFuture
    .supplyAsync(() -> fetchUser(userId))
    .thenCompose(user -> validateUser(user))
    .thenApply(user -> generateReport(user));
    // 无异常处理！错误静默消失！
```

**问题诊断**：
- 异常在链中丢失，无法调试
- 无日志、无metrics

**正确方案**：
```java
.whenComplete((result, exception) -> {
    if (exception != null) {
        log.error("Failed to process user {}", userId, exception);
    }
})
.handle((result, exception) -> {
    if (exception != null) {
        return "Error: " + exception.getMessage();
    }
    return result;
});
```

## 模式积累

### 并发集合选择决策树
```
是否需要并发安全?
├── 否 → 使用普通ArrayList/HashMap
└── 是
    ├── 读多写少 + 需要索引 → CopyOnWriteArrayList
    ├── 高并发队列 → ConcurrentLinkedQueue
    ├── 线程安全Map → ConcurrentHashMap
    └── 复合操作 → 避免synchronized*，用Concurrent*+lambda
```

### Virtual Threads最佳实践
- ❌ 禁止：synchronized方法/块
- ✅ 推荐：ReentrantLock + tryLock超时
- ✅ 推荐：Semaphore控制并发数

### CompletableFuture异常处理模板
```java
.completableFuture
    .whenComplete((result, ex) -> {
        if (ex != null) log.error("...", ex);
    })
    .handle((result, ex) -> {
        if (ex != null) return fallbackValue;
        return result;
    });
```
