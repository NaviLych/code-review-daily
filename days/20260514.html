Rule: Cross Before You Use — 一旦跨越信任边界，每个库调用都可能是攻击者的代码

⚠️ Bug-for-Bug兼容性是安全特性
// kill -1 在GNU和uutils中有不同语义 GNU: kill -1 → 请求信号1的PID uutils: kill -1 → 发送给PID -1 → kill所有可见进程! // 一个typo变成系统级kill开关

Hyrum's Law: 可观测的行为都会被依赖。行为兼容性是安全特性。

🔄 双重Syscall检查

触发条件：代码对同一路径执行两个操作
  • 两个操作之间是否可能修改文件系统？
  • 第二个操作是否会跟随symlink？
  • 是否可以使用原子操作替代？

🎭 类型边界守卫

触发条件：char/Unicode到字节的转换
  • 是否有显式的#[allow(trivial_casts)]？
  • 是否有输入验证（ASCII范围）？
  • 是否可以使用bytes()迭代器替代？

🏰 信任边界标记

触发条件：跨越信任边界（chroot、sandbox、权限提升）
  • 边界前的数据是否已解析完成？
  • 边界后的库调用是否可控？
  • 是否有NSS/动态库加载风险？

📝 今日关键教训

  • Rust的borrow checker不保护TOCTOU：它只在内存安全层面有效，文件系统状态在外部
  • 编译器警告是最后防线：Ghost Bits漏洞需要显式忽略警告才能利用
  • Swift 6.0的严格并发检查：@preconcurrency是技术债，不是解决方案
  • 跨语言智慧：TOCTOU是所有语言的共同问题，但解决API不同
  • 信任边界原则：一旦跨越边界，每个库调用都可能是攻击者的代码
