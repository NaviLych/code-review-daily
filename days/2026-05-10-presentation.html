🔴 Java: Double-Checked Locking 经典陷阱

// ❌ 有缺陷的代码 (AI 常见生成)
public class ResourceFactory {
    private static Resource resource;

    public static Resource getInstance() {
        if (resource == null) {
            synchronized (ResourceFactory.class) {
                if (resource == null)
                    resource = new Resource(); // 可能返回部分构造对象!
            }
        }
        return resource;
    }
}
⚠️ 问题: JVM 可能重排序构造函数和字段赋值，导致线程B看到非null但未构造完成的对象

来源: SonarSource - GPT-5.5's biggest blind spot

✅ Java: Double-Checked Locking 修复方案

方案1: synchronized 方法 (推荐)

public static synchronized 
    Resource getInstance() {
    if (resource == null)
        resource = new Resource();
    return resource;
}

方案2: Holder 模式 (最佳)

private static class Holder {
    public static Resource 
        resource = new Resource();
}

public static Resource getInstance() {
    return Holder.resource;
    // JVM 保证线程安全
}
💡 洞察: 现代 JVM 的 synchronized 开销已可接受，性能论据不再成立

🔴 Java: 在 Boolean 上 synchronize 隐蔽陷阱

// ❌ 危险代码
private static final Boolean bLock = Boolean.FALSE;

public void doSomething() {
    synchronized (bLock) { // 与所有 Boolean.FALSE 用户共享锁!
        // critical section
    }
}
⚠️ 问题: Boolean.valueOf() 缓存 -128~127，所有线程共享同一对象！
Integer、String、List.of() 同样危险
✅ 修复: private final Object lock = new Object();

🟡 Swift: 串行 vs 并行执行 性能陷阱

❌ 串行 (错误)

// 总耗时 = t1 + t2 + t3
let user = await getUser()
let address = await getAddress(of: user)
let payment = await getPayment(of: user)

每个调用必须等前一个完成

✅ 并行 (正确)

// 总耗时 = max(t1, t2, t3)
async let user = getUser()
async let address = getAddress(of: user)
async let payment = getPayment(of: user)

let (u, a, p) = try await (user, address, payment)

同时启动，最后统一 await

🔴 Swift: Task 隐式捕获 self 内存泄漏

@MainActor
class ViewModel {
    func listenToNotifications() {
        Task {
            // ⚠️ self 被隐式捕获，Task 永不结束
            let notifications = NotificationCenter.default.notifications(
                named: UIDevice.orientationDidChangeNotification
            )
            for await notification in notifications {
                self.handle(notification)  // 强引用 self!
            }
        }
    }
}
⚠️ 问题: Task 持有 ViewModel 引用，而无限序列让 Task 永不结束 → 内存泄漏

来源: 3 mistakes to avoid with async/await

✅ Swift: Task 内存泄漏修复

@MainActor
class ViewModel {
    func listenToNotifications() {
        Task { [weak self] in
            guard let self else { return }
            
            let notifications = NotificationCenter.default.notifications(
                named: UIDevice.orientationDidChangeNotification
            )
            
            for await notification in notifications {
                self.handle(notification)
                // ✅ 循环内部 unwrap
            }
        }
    }
}
💡 关键点: [weak self] 必须在 for 循环内部 unwrap，而非外部！

🟡 Swift: Task.detached 滥用 过度设计

@MainActor
class ViewModel {
    func listenToNotifications() {
        Task.detached { [weak self] in
            // ⚠️ 脱离 @MainActor 上下文
            let notifications = await NotificationCenter.default.notifications(
                named: UIDevice.orientationDidChangeNotification
            )
            
            for await notification in notifications {
                guard let self else { return }
                await self.handle(notification)  // 需要额外 await
            }
        }
    }
}
💡 建议: 优先使用普通 Task，只有确实需要脱离上下文时才用 Task.detached

🔴 Java 25: ScopedValue 与 ExecutorService 新特性陷阱

static final ScopedValue REQUEST_ID = ScopedValue.newInstance();

void handleRequest(String id) {
    ScopedValue.where(REQUEST_ID, id).run(() -> {
        executor.submit(() -> { // ⚠️ 线程来自线程池
            String reqId = REQUEST_ID.get(); // NoSuchElementException!
            processAsync(reqId);
        });
    });
}
⚠️ 问题: ScopedValue 绑定不传播到 ExecutorService 的工作线程！
必须使用 StructuredTaskScope 才能继承绑定

来源: Your AI can write Java 25 right

✅ Java 25: ScopedValue 正确用法

void handleRequest(String id) throws Exception {
    ScopedValue.where(REQUEST_ID, id).call(() -> {
        try (var scope = StructuredTaskScope.open(
                Joiner.allSuccessfulOrThrow())) {
            scope.fork(() -> {
                String reqId = REQUEST_ID.get(); // ✅ 正确继承
                processAsync(reqId);
                return null;
            });
            scope.join();
        }
        return null;
    });
}
✅ 关键: 使用 StructuredTaskScope 创建的子任务才能继承 ScopedValue 绑定

🔴 Java 25: ScopedValue.where() 结果被丢弃

❌ 错误

static final ScopedValue 
    THEME = ScopedValue.newInstance();

// ⚠️ Carrier 结果被丢弃
ScopedValue.where(THEME, "DARK");

// 抛出 NoSuchElementException
String theme = THEME.get();

✅ 正确

// ✅ 正确消费 Carrier
ScopedValue.where(THEME, "DARK")
    .run(this::renderUI);

// 或
ScopedValue.where(THEME, "DARK")
    .call(() -> {
        // 在此作用域内有效
        return null;
    });
